# StayLocal backend

Емуляція процесу релізу для ЛР3 з «Проектування інформаційних систем».

Стратегія: trunk-based з короткими feature-гілками + гілки release і hotfix.

- `main` — єдине джерело правди, зміни лише через pull request (Gate 1);
- `feature/<ID>-<опис>` — одна задача з ID вимоги, живе 1–2 дні;
- `release/x.y` — фіксує зміст релізу, з неї збираються теги `vx.y.z`;
- `hotfix/x.y.z` — від тегу, зливається в `release/x.y` і в `main`.
